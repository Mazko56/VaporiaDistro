# VAPORIA DISTRO — Telegram Mini App + бот + PostgreSQL

**Оновлення 2026-10-09:** додано перевірку підпису Telegram через офіційний Ed25519 як незалежну альтернативу HMAC, тест офіційного прикладу й безпечну діагностику. Деталі: `ВИПРАВЛЕННЯ_AUTH_ІНСТРУКЦІЯ.txt`.

**Версія 1.0.0 • функціональний MVP / вихідний код для Railway**

Брендинг зроблено за наданим логотипом **VAPORIA DISTRO**; приклади екранів XSMOK використані лише як **зразок структури**. Інтерфейс — premium dark / smoke / chrome / electric blue + violet. У цьому архіві є **справжній фронтенд, API, Telegram-бот, SQL-схема, тестові товари та адмінпанель**, а не лише макет.

> **ВАЖЛИВО:** продаж вейп-продукції регулюється законом. За замовчуванням продакшен-оформлення **ВИМКНЕНО** (`ENABLE_CHECKOUT=false`). Перед включенням потрібна перевірка ліцензування, правил реклами/бонусів, перевірки віку та порядку продажу. Див. `docs/LEGAL_LAUNCH.md`. Вбудований age-gate є лише самодекларацією, а не повноцінною ідентифікацією.

- Продакшен QA з реальним токеном, доменом, платіжним провайдером та пристроями Android/iOS.

## Стек

- **TypeScript** — єдина мова бота, серверу та інтерфейсу.
- **React 18 + Vite 6** — швидкий Mini App (SPA).
- **Node.js 22 + Express 4** — REST API та статичний сайт одним процесом.
- **grammY** — Telegram bot + webhook.
- **PostgreSQL 16/17** — постійне сховище, транзакції оформлення та бонусів.
- **CSS + Lucide** — власна дизайн-система, адаптація під мобільні.

Цей стек краще за PHP для такого проєкту, бо підходить для єдиного TypeScript-коду клієнта і сервера, є хороша підтримка Telegram API, а Railway може запускати все без Docker. Окремий NestJS/NextJS у цьому MVP створив би непотрібний оверхед.

## Запуск локально

Встановіть **Node.js 22+**, **PostgreSQL**, Git. Створіть базу `vaporia` і користувача із правами на CREATE TABLE.

```bash
npm install
cp .env.example .env       # на Windows скопіюйте файл вручну
```

Налаштуйте `.env`:

```env
DATABASE_URL=postgresql://postgres:пароль@localhost:5432/vaporia
NODE_ENV=development
SESSION_SECRET=довгий_випадковий_рядок_мінімум_32_символи
DEV_AUTH_ENABLED=true
ENABLE_CHECKOUT=true
SEED_DEMO_DATA=true
```

Запустіть:

```bash
npm run dev
```

Відкрийте `http://localhost:5173`. Режим розробки автоматично входить під демо-користувачем, адміністратор також доступний для тестування. API — `http://localhost:3000/api/health`. На першому старті автоматично створюються таблиці та, якщо `SEED_DEMO_DATA=true`, тестовий каталог. Щоб виконати міграції окремо: `npm run db:migrate`.

**Тільки у development** доступний dev-вхід. У Railway встановіть `NODE_ENV=production`, `DEV_AUTH_ENABLED=false`.

## Telegram-бот працює, але Mini App повідомляє про невірний підпис

Після версії виправлення бот виконує `await bot.init()` перед прийманням webhook-оновлень. У логах після запуску має бути рядок `Telegram bot initialized as @ВАШ_БОТ`. Переконайтесь, що це саме бот, у якому відкривається Mini App (наприклад, `@vaporiadistro_bot`). Якщо ім’я інше, неправильний `BOT_TOKEN` в Railway.

У разі помилки Telegram-авторизації в логах з'явиться лише код `signature_mismatch`, `expired`, `future_date` або `invalid_format` — сам токен, хеш та initData не виводяться. `signature_mismatch` найчастіше означає, що Mini App відкрито через іншого бота, ніж той, чиї дані записані в `BOT_TOKEN`. `expired` означає, що потрібно **повністю закрити** Mini App у Telegram і запустити його з меню бота повторно. Не вимикайте перевірку HMAC та не вмикайте `DEV_AUTH_ENABLED` на Railway.
